# Сайт БТИ Самара — ИП Баймурзин А. Р.

Лендинг кадастрового инженера. **К проекту Fortune VPN отношения не имеет** — это
отдельный сторонний проект, свой репозиторий, свои деплои.

## Как выкладывать

Двойной клик по `DEPLOY.bat` в корне: `git push origin main` (зеркало GitHub Pages,
~40 секунд), `railway up --ci` (API заявок и зеркало, ~1 минута) и заливка на
kadastrhelp.ru по SSH (основной сайт, секунды).
Из сессии Claude, запущенной в репозитории Fortune VPN, деплой блокирует его защитный хук —
выкладывает владелец батником.

⚠️ Не копировать файлы через `git archive`: при `core.autocrlf=true` он переводит
`assets/vendor/react*.min.js` в CRLF, хеш SRI перестаёт совпадать и страница остаётся пустой.

## Как устроен сайт

Client-rendered на **dc-runtime**: `support.js` разворачивает `<x-dc>`, `<dc-import>`,
`sc-for`, `sc-if`. Компоненты — `*.dc.html`, логика в `class Component extends DCLogic`.
Картинки-слоты — `image-slot.js` + `.image-slots.state.json` (dotfile с base64).
С 30.09.2026 фото героев главной и межевания — обычные `<img>` из `assets/photos/`
с `preload` в `<head>` (слот ждал 346 КБ base64 обоих фото, LCP 5–8 с на медленном 4G);
в слоте остался только `about-portrait`, sidecar пустой. Сменить фото = положить
новый файл под новым именем (nginx reg.ru кэширует статику долго) и поправить `src`
и `preload`.

Раздаётся `server.js` — Node без зависимостей: слушает `$PORT`, страницы отдаёт по
чистым адресам (см. «Адреса страниц»), HTML/JS с `no-cache`, картинки на сутки. Отдаёт только файлы из
явного списка (`isPubliclyServable`) — `server.js`, `package.json`, `CLAUDE.md` и прочее
служебное дают 404. Он же принимает заявки — см. «Заявки с сайта» ниже.

Локально посмотреть:
```
PORT=3999 node server.js
```

**Режим правок** (26.09.2026). Ссылка с `?review=1` — например
`https://downmeansoff.github.io/bti-samara/?review=1` — включает поверх сайта панель
«Заметка / Рисунок / Отменить / Правки»: метки с текстом и картинкой, рисование пальцем или
мышью. Код — `assets/review.js`; в `<head>` пяти страниц однострочный загрузчик, который
тянет его только при `?review=1` или флаге `bti_review` в sessionStorage вкладки —
посетителям файл не грузится. Правки лежат в localStorage браузера, наружу — «Скопировать
текст» или файл `bti-pravki-*.json`. Скриншоты с метками по файлу:
`node C:/Users/glebo/bti-lab/tools/review-render.mjs` (без `--in` берёт свежий файл из
«Загрузок»). Проверка: `review-test.mjs` там же. Редирект с `/` (`index.html` и `server.js`)
сохраняет query — иначе ссылка с `?review=1` на корень теряла бы параметр.

**Вся вёрстка — в `assets/site.css`**: токены цветов и шрифтов, компоненты, адаптив.
Разметка страниц на классах.

`<title>`, description, `og:*`, иконка и canonical лежат в статическом `<head>`, а не в
`<helmet>`. Helmet вставляет теги JavaScript-ом, а боты превью ссылок (Telegram, WhatsApp,
ВК) JS не запускают — до 24.09.2026 из-за этого обложка в превью не показывалась.
В `<helmet>` остались только стили. У корневого `index.html` (редирект) свой набор og-тегов —
это его ссылку раздают. Canonical главной — `https://kadastrhelp.ru/`.

## Заявки с сайта (с 28.09.2026)

Окно заявки (`LeadModal.dc.html`) отправляет `POST` на `/api/lead` — на Railway и
localhost тот же origin, на github.io — `BTI_CONTACTS.leadApi` (Railway). Таймаут 8 с.
На kadastrhelp.ru сначала свой адрес `/api/lead.php` (`hosting/api/lead.php`, 10 с): он
пересылает заявку на Railway с сервера хостинга — для провайдеров, режущих
`*.up.railway.app`. Секрет `LEAD_RELAY_SECRET` лежит на Railway и в
`~/lead-relay.secret` на хостинге (вне сайта, права 600); с ним `server.js` считает лимит по
IP посетителя из `X-Lead-Client-IP`, а не по одному IP хостинга. Напрямую на Railway форма
идёт, только если заявка точно не дошла (404, 5xx кроме 504); после 504 и таймаута — нет,
чтобы не задвоить. ⚠️ Прод-API шлёт настоящие заявки: не отправлять форму на живых
адресах из тестов, `tools/qa-r2-functional.mjs` подменяет `fetch` внутри страницы. Успех: «Заявка отправлена. Кадастровый инженер свяжется с
вами.» Отказ или таймаут: текст копируется в буфер и появляется кнопка «Отправить
через Telegram» (`t.me/kadastricom_bot?text=…`) — сама ничего не открывает.

`server.js` проверяет origin (github.io, kadastrhelp.ru с www и без, Railway), поля,
скрытое поле-ловушку `website`, лимиты (5 заявок за 10 минут с IP — IP берётся из
последнего звена `X-Forwarded-For`; 60 в час на всех) и шлёт заявку ботом
`@kadastricom_bot` в каждый чат из `TG_LEAD_CHAT_IDS`. Что клиент напишет самому боту,
тоже пересылается туда. Логи Railway: `LEAD_OK id`, `LEAD_UNDELIVERED` (заявка целиком —
только когда Telegram не принял), `OWNER_REGISTER chat=<id>`, `BOT_UNDELIVERED` (то, что
клиент написал боту, а Telegram не переслал: текст или подпись и `file_id` — в логе).

Переменные Railway (сервис `bti-samara-landing`): `TG_BOT_TOKEN`, `TG_LEAD_CHAT_IDS`
(через запятую), `TG_WEBHOOK_SECRET` (путь `/tg/<секрет>` и заголовок
`X-Telegram-Bot-Api-Secret-Token`), `TG_OWNER_CODE`, `TG_API_BASE` (только для тестов).
Обложка меню и пять фото альбома «Документы и награды» Telegram тянет сам по URL. С
`kadastrhelp.ru` (общий хостинг) он их почти не получает — живой тест 02.10: «failed to get

бот отдаёт эти адреса со своего сервера: `BOT_ASSET_ORIGIN` (необязательно, `https://хост`),
иначе `RAILWAY_PUBLIC_DOMAIN` (Railway выставляет сам), иначе адрес сайта. Ссылки запасного
текста документов остаются на сайт (их открывают в браузере). После деплоя, который меняет
эти адреса или файлы, проверять живым прогоном: `sendMediaGroup` и `sendPhoto` с теми же
URL в свой чат.

## Бот (Telegram, меню и заявка в чате)

Бот — не только пересылка сообщений боту: `/start` открывает меню с разделами сайта
(услуги, цены, как работаем, о компании, отзывы, вопросы, контакты) и отдельный флоу
«Оставить заявку» с шагами услуга → имя → телефон → комментарий → подтверждение.
Навигация — одно сообщение, которое редактируется на месте (`editMessageText`), а не
десяток новых.

Три файла, в таком порядке данных:

- **`bot-content.js`** — СГЕНЕРИРОВАННЫЙ файл, руками не трогать. Его делает
  `gen-bot-content.mjs`, вытягивая тексты/цены/FAQ прямо из `.dc.html`-страниц,
  `Footer.dc.html` и `LeadModal.dc.html` (часть строк — через `vm`-разбор
  `const ARRAY = [...]`, часть — через проверку, что совпадает с заранее вписанной
  цитатой с её страницы). После **любой** правки текста или цены на сайте —
  `node gen-bot-content.mjs`, иначе бот покажет старое. `node gen-bot-content.mjs --check`
  проверяет, что файл не разошёлся с сайтом (без сети, без побочных эффектов; переводы
  строк CRLF/LF не важны — на этой машине `core.autocrlf=true`). Генератор падает с
  ненулевым кодом и в обычном запуске, и в `--check`, если: обязательный блок пуст или
  пропал (услуги, шаги, чек-листы, цены, общий FAQ и FAQ межевания/техплана, отзывы,

  строки `PRICE_ROWS` с той же подписью; генератор падает, если на этих местах
  `LM_SERVICES` стоит другая услуга или строки цены с такой подписью нет.
- **`bot-ui.js`** — чистые функции: экраны, разбор `callback_data` (`route()`), подсказки

  без отсебятины. Все поиски по ключам из `callback_data` — только по собственным ключам
  (`constructor`, `__proto__`, `toString` не проходят).
- **`server.js`** — всё остальное: приём `/tg/<секрет>`, вызовы Telegram, Map состояния
  заявки `chatId -> {step, service, name, phone, comment, kb, back, promptId, oldPrompts,
  busyIds, failed, capLogged, t}` (TTL 30 минут, чистится тем же интервалом, что и
  рейт-лимиты). `step`: `service | name | phone | comment | confirm | edit | done`;

Грамматика `callback_data` (коротко, видно в `bot-ui.js:route()`): `m` меню, `s`/`s:<id>`
услуги и услуга (`mezh`/`tehplan`/`razdel` со страницей на сайте, `obsl`/`osmotr`/`vynos` —
короткий экран: название, цена, «Оставить заявку»), `s:<id>:w`/`:f`/`:q<n>` этапы/вопросы
услуги (только у трёх со страницей), `p` цены, `h` как работаем,
`h:d` что вы получите на руки, `a`/`a:p`/`a:d` о компании/проекты/документы, `r` отзывы,
`f`/`q<n>` вопросы и ответ, `c` контакты, `l` начать заявку (`l:<id>` — сразу с услугой),
`l:o<n>` выбор услуги, `l:me`/`l:skip`/`l:ok`/`l:x` — шаги заявки, `l:e` «Что изменить?»,
`l:e:s`/`l:e:n`/`l:e:p`/`l:e:c` — изменить услугу/имя/телефон/комментарий (после ввода
сразу назад к подтверждению, флаг `back`), `l:b` — назад к заявке. Любой другой `l:*`
(старое `l:edit`, неизвестный id) — устаревшая кнопка. Старые `services`/`contacts`
(до редизайна) по-прежнему резолвятся — для чужих ссылок, если такие ходят.

Как флоу отвечает на кнопки и ввод:

- **Очередь по чату.** Апдейты одного чата обрабатываются строго по одному, в порядке
  прихода (цепочка промисов на чат, `enqueueForChat`); ждать могут не больше 20, лишние
  молча отбрасываются; ошибка одного апдейта не рвёт цепочку. Лимит меню для нажатий
  кнопок (40 в минуту) считается на входе, до очереди. Состояние меняется до первого
  `await`.
- **Кнопки флоу** (все `l:*`, кроме `l`, `l:<id>` и `l:x`) действуют только на
  сообщениях своего флоу: `promptId` (текущая подсказка) и `oldPrompts` (прежние);
  ответы лимитов (`busyIds`) не в счёт. Принадлежность проверяется раньше шага.
  Сообщение не этого флоу (флоу нет, протух, рестарт, экран прежнего флоу) — тост
  «Заявка устарела — начните заново.» и это сообщение превращается в меню. Своё
  сообщение, но не тот шаг (двойной тап) — молча. Когда шаг уходит в новое сообщение,
  кнопки прежней подсказки гасятся.
- **После отправки** (`done`) любая кнопка флоу — только тост «Заявка уже отправлена.»,
  экран не трогается; `l`/`l:<id>` начинают новую заявку как обычно. Если заявку не
  принял ни один чат (`failed`), тоста нет (экран «не получилось» уже дал контакты) и
  повторной отправки нет: Telegram мог принять заявку и не успеть ответить, повтор
  задвоил бы её. `l:x` и набранная отмена после отправки закрывают флоу и ведут в меню
  с ответом «Заявка уже отправлена.», а при `failed` — «Заявка отменена.».
- **Reply-клавиатура телефона** (флаг `kb`): снимается только отдельным сообщением с
  `remove_keyboard` (одно сообщение не может нести и её, и inline-кнопки). Успех —
  «Телефон: …» (без `parse_mode`); отмена любым путём — «Заявка отменена.»; перезапуск
  (`l`, `l:<id>`, `/request` при `kb`) — «Начинаем заново.», и новый флоу новым
  сообщением под ним; навигация и команды при `kb` — «Заявка отменена.».
- **Отмена.** `l:x` — тост «Заявка отменена.» и сообщение превращается в меню. Набранное
  «Отмена» (регистр не важен, можно с точкой) и `/cancel` отменяют на любом шаге и даже
  когда флоу уже нет (клавиатура могла остаться): инженеру не уходит, ответ —
  «Заявка отменена.» с `remove_keyboard`, затем меню новым сообщением.
- **Что шаг не принял**, идёт обычной дорогой пересылки, флоу не сбрасывается и не
  двигается: текст на шагах с кнопками (выбор услуги, подтверждение, «Что изменить?»),
  фото/файлы/видео на любом шаге, контакт не на шаге телефона — тот же лимит 5 в минуту,
  те же альбомы, тот же ответ «Сообщение передано. Кадастровый инженер свяжется с вами.…».
  Контакт без флоу пересылается, ответ снимает reply-клавиатуру. Служебные сообщения
  (таймер удаления, закреп, название чата и т. п.) и пустой после trim текст молча
  игнорируются: ни пересылки, ни ответа, ни слота лимита.
- **Пересылка инженеру.** Над каждым сообщением — заголовок «💬 Сообщение в боте»,
  «Имя: …» из профиля и та же строка `Telegram:`, что в заявке из бота (ссылка
  `tg://user?id=<id>` с `@username` или именем; при нечисловом id — без ссылки). Текст
  уходит одним сообщением под заголовком, длинный обрезается до лимита Telegram по
  границе символа (так же режется комментарий в заявке, и с сайта, и из бота). Фото,
  файл, контакт — сначала заголовок отдельным сообщением, потом `forwardMessage` (у
  альбома заголовок только перед первым элементом). Telegram не принял ни одной копии —
  `BOT_UNDELIVERED` в лог, клиенту «Не получилось передать сообщение инженеру —
  позвоните или напишите напрямую.» с контактами и [← Меню] (заявка из бота в том же
  случае — «Не получилось передать заявку инженеру — …», тоже с контактами и [← Меню]).
- **Телефон** (набранный или контакт) проверяется той же `phoneOk()`, что и форма сайта;
  чужой контакт (`user_id` ≠ отправитель) не принимается; иностранный номер из контакта
  без «+» получает «+». **Имя** чистится от невидимых и управляющих символов (и от
  пустых «букв»: хангыль-заполнители U+115F, U+1160, U+3164, U+FFA0, пустой шрифт Брайля
  U+2800, U+17B4, U+17B5, U+180E) и должно содержать букву.
- **Согласие.** На экране подтверждения — дословная подпись чекбокса сайта со ссылкой на
  политику, кнопка «Согласен, отправить». В заявке инженеру после строки `Telegram:` —
  «Согласие на обработку персональных данных: дано в боте» (только у заявок из бота).
- **Лимиты на `l:ok`**, в порядке проверки: свой лимит чата (5 заявок за 10 минут, ключ
  `tg:<chat>`) — «Слишком много заявок подряд. Попробуйте позже или свяжитесь по
  контактам.» с кнопками [Контакты] [← Меню]; минутный лимит чата (5 в минуту, общий с
  пересылкой) — «Слишком часто. Подождите минуту.»; общий часовой (60 заявок в час на
  сайт и бота вместе) — в лог `LEAD_UNDELIVERED` с `"reason":"rate_limited","source":"bot"`
  и данными заявки (одна строка на флоу, ещё одна — только если клиент поменял данные),
  клиенту «Сейчас много обращений. Попробуйте позже или свяжитесь по контактам.» с
  кнопками [Контакты] [← Меню]. Подтверждение при любом отказе остаётся живым (кнопки
  ответа флоу не закрывают), повторное нажатие — новая попытка. Лимит альбома
  документов (`a:d`) — 3 в минуту на чат.

Правила экранов (FIXES.md, раздел B): каждый экран, кроме подсказок шагов заявки и
сообщения с reply-клавиатурой, кончается рядом с «← Меню»; две кнопки в ряд — только если
обе подписи не длиннее 17 символов (пары «← X» / «← Меню» и цифровые кнопки списков
вопросов, по три в ряд, — исключение); маркер списка `• `; внутри цен пробелы — U+00A0
(`nbspPrice()`), цена не рвётся на границе строки.

Владелец (чат из `TG_LEAD_CHAT_IDS`) может пройти весь флоу заявки сам — она уйдёт
только ему же, с пометкой «🧪 Тестовая заявка из бота» в тексте, в лог так же пишется
`BOT_LEAD_OK`, но ни в один боевой чат заявка не попадает.

Логи Railway, специфичные для бота (сверх уже описанных `LEAD_OK`/`OWNER_REGISTER`
выше): `BOT_LEAD_OK <id>` — заявка из бота доставлена; `LEAD_UNDELIVERED` с
`"source":"bot"` в JSON — заявка из бота не доставлена ни в один чат (клиенту показан
текст «не получилось» и контакты) или отказана общим часовым лимитом
(`"reason":"rate_limited"`); `BOT_UNDELIVERED` — свободный текст/фото клиента боту
не переслалось; `BOT_TG_ERR <method> <status> <description>` — любой неудачный вызов
Telegram из кода бота, кроме `message is not modified` (это не ошибка, а штатный повтор
того же экрана).

## SEO

Подробно — `SEO.md`. Коротко: страницы рисуются JavaScript-ом, поэтому `pack-hosting.mjs` делает для
роботов поисковиков готовые копии (`make-snapshots.mjs` → `_snap/`, правила в `.htaccess`, посетители
получают живую страницу). Структурированные данные строятся из тех же массивов, что и текст страниц:
после правки FAQ или цены на странице запусти `node seo-markup.mjs`. Три посадочные
(`vynos-tochek`, `akt-obsledovaniya`, `akt-osmotra`) генерируются из `landings-data.mjs`
(`node gen-landings.mjs`), руками их не править; в них только цены из прайса владельца, без сроков
и юридических обещаний. Новая страница = слаг в `server.js` (`PAGE_SLUGS`), в трёх списках
`pack-hosting.mjs`, в `404.html`, в `sitemap.xml`, в меню (`Header`/`Footer`). Проверка: `node tests/seo-check.mjs`.
Тексты посадочных перед выкладкой читает инженер.

Аналитика (Яндекс Метрика): `assets/analytics.js`, выключена (`metrika: 0`), включается номером счётчика и датой
`policyDate`; политика конфиденциальности переключает формулировку вместе со счётчиком. Вебвизор не включать.
Цели: `lead_open`, `lead_sent`, `click_phone|telegram|max|email`. Проверка: `node tests/analytics-check.mjs`.
Подробно — раздел «Аналитика» в `SEO.md`.
